# KiraAI_xml_tag_fixer_plugin/掉消息标签修复插件1.5.1

[![Ask DeepWiki](https://deepwiki.com/badge.svg)](https://deepwiki.com/znq19/KiraAI_xml_tag_fixer_plugin)

修复AI未正确包裹标签导致用户无法看到消息的问题，自动补全 AI 输出中缺失的 &lt;msg> 和 &lt;text> 标签

## 0.功能介绍

该插件通过自动后处理的方式，辅助KiraAI官方的xml修复，修正一些AI模型（例如deepseek，例如deepseek，例如deepseek）经常不正确带<text><msg>标签导致用户无法看到消息的问题。

简单说，装了这个能大大减少AI（尤其是D指导）不带标签直接发消息你看不到的神秘情况！

同时，修复一些模型因渠道限制、降智等缘故兼容xml格式失败而产生错误的双尖括号问题（例如&lt;&lt;msg>）和at效果不真实问题。

修复后的内容会作为 AI 的历史消息写入记忆——AI 在记忆里看到的都是良构格式示例，后续输出会越来越规范，形成正循环。

### 1.5.1 修复

- **未注册标签（`reasoning` / `thinking`）的两个结构保护改为无条件执行**：
  - 修复**关闭**总开关时 `<reasoning>` 里的 `<msg>` 草稿被当真消息发出（`_protect_stray_blocks` 原被总开关挡住）。实测 `<reasoning>草稿<msg><text>示例</text></msg></reasoning><msg><text>正式</text></msg>` 会同时发出「示例」和「正式」，现在只发「正式」。
  - 修复**开启**总开关时未闭合 `<reasoning>` 把后面真消息吞掉。原逻辑对未注册标签是「剥到末尾」，`<reasoning>我在想……<msg><text>真消息</text></msg>` 会整条丢光；现在改为**在下一个 `<msg>` 之前补上闭合**，把它封成一个完整的未注册标签块。
- **未注册标签块在关闭总开关时也保留**（原样透传）：框架对 root 级未注册标签本来就是「静默跳过」——用户看不到，但原文进记忆。保留它，模型才能在历史里看到自己用 `<reasoning>` 包规划的范例，不会逐渐忘记这个约定（1.2.1 正是为这个才把它从「剥离」改成「保留」）。
- **关闭总开关时的散段分流最终形态**：
  | 散段内容 | 处理 |
  |---|---|
  | 裸文本（模型规划 / 旁白 / 心声） | **丢弃**（这正是总开关要挡的） |
  | 未注册标签块（`reasoning` / `think`） | **原样透传**（用户不可见，原文进记忆） |
  | 忘带 `msg` 的已注册功能标签（语音 / 图片 / @ / 表情） | **补包**（真修复目标，丢了就是功能静默失效） |
  | 含 `[xxx]` 标记的文本 | **补包**（保折扇留穗等插件的跨消息协议） |
- **新增 `tests/test_unregistered_tags.py`**：59 条断言覆盖 21 个场景 × 开/关两态，验证「心声不泄漏」与「真消息不丢失」两条不变量。
- **修复配置迁移实质失效的问题（重要）**：1.5.0 的迁移靠「配置里有没有该键」判断用户是否配过 —— 但框架会把缺失的键用默认值补齐并落盘，所以**跑过 1.4.0 的用户文件里必然已有该键（值 `true`）**，迁移被误判为「用户显式配置过」而保留 `true` ⇒ 对老用户**完全没生效**，心声照旧泄漏。现改为按**值**判断（`true` = 旧默认 ⇒ 迁移为 `false`），并**回填当前实例**让迁移立即生效（原先要等重载）。迁移仍**只做一次**：之后用户手动打开不会被改回（已用测试锁定）。

### 1.5.0 新增（可解析性硬闸门 + 13 项缺陷修复 + 隐私默认调整）

- **「处理 msg 外杂散内容」默认改为关闭（隐私）**：开启时模型写在 `<msg>` 外的**规划/心声**会被当消息发出（实测泄漏 `让我想想…我该查一下`、`等等先确认城市`）。关闭后这些不再发出去，**但不影响修复能力** —— 忘包 `<msg>` 的功能标签（语音/图片/@/表情）与含 `[xxx]` 标记的文本仍自动补包（细粒度分流，只挡裸文本）。
- **一次性配置迁移（原子写、失败不覆盖）**：1.5.0 首次运行迁移一次 —— 未显式配置过的用户迁到新默认，已配过的尊重原值，写标记后不再干预。详见「已知的bug #3」。
- **散段细粒度分流**：关闭总开关时，只丢裸文本（心声）；保留并补包功能性内容（注册标签 / `[xxx]` 标记），未注册标签（`reasoning`/`think`）**原样透传**（用户看不到、原文进记忆，模型不会忘掉这个约定）。
- **未注册标签（`reasoning`/`think`）两个结构保护改为无条件执行**：详见 1.5.1。


> **核心认识：框架对整段输出只有一次解析机会。**
> `core/message_manager.py` 的 `send_xml_messages` 只做一次
> `ET.fromstring("<root>" + xml_data + "</root>")`，解析失败就
> `logger.error("Error parsing message")` 并 **return []** ——
> **本轮一条消息都发不出去**。所以本插件真正的最高不变量不是"修得漂亮"，
> 而是"**输出必须能被框架解析**"。1.5.0 把这条不变量落成了代码里的硬闸门。

- **逐块闸门 + 总闸门**：每个修复后的块都要过 `ET.fromstring` 校验，不过的先抢救（剥壳清洗）、仍不过则丢弃；整段拼好后**再校验一次**，还不过就走总闸门（整段清理为一条纯文本消息）。宁可少发一条，也不让一轮全灭。
- **修复 `<\\/msg>` 反斜杠转义标签**（新增配置项 `fix_backslash_tags`，默认开）：模型从 JSON/正则习惯串味时会写 `热搜榜！<\\/msg>`，旧版**完全没有处理**，它被当成普通文本转义成 `&lt;\\/msg&gt;` 原样发出去，用户就在消息末尾看到一串 `<\/msg>` 乱码。现在会还原成真闭合标签。
- **修复"合法输入被弄坏"的 8 类回归**（最严重的一类：本来能正常发的消息，被修成整轮发不出）：
  - **嵌套 `<msg>` 的切块**：旧版用 `find("</msg>")` 找闭合，模型写草稿/示例导致嵌套时会把内层 `</msg>` 误当外层闭合，切出 `</text></msg>` 这样的残片 → **整轮不可解析**。现在按**嵌套深度配对**切块。
  - **同名嵌套标签**：旧版正则 `(.*?)</\1>` 在 `<foo>a<foo>b</foo>c</foo>` 上把内层闭合当外层闭合 → 修完变成缺闭合的坏 XML。现在用"内部不得再出现同名开口"约束。
  - **`_fallback_wrap` 把坏块原样吐回**：清洗后为空时旧版返回**原始坏块**，等于把残片直接塞回结果。现在返回空并丢弃（由总闸门兜底）。
  - **`<msg/>` 混用**：`<msg><text>hi</text><msg/></msg>` 现在正确切块。
- **修复"输入坏但救不回"的 7 类**：
  - **裸闭合标签**（`</text>`、`</msg>`、`<msg>...</msg></text>`）
  - **text 里出现 `</msg>` 字面量**（打字打错闭合标签名）
  - **XML 非法控制字符**（`\x01`、`\x00` 等，会让整段解析失败）
  - **多个未闭合 root 标签**（`<record a><record b>`）—— 旧版处理完第一个就 return
- **内容损坏修复（不再静默改内容）**：
  - `<<` 不再无差别折叠：`a<<b`、`1<<2`、`vector<<T>` 里的运算符不再被吃掉（旧版一律替换成 `<`，属于正文损坏）。
  - **tail 不再丢失**：`<text>a<at>1</at>b</text>尾巴` 里的"尾巴"、合并标记对时的块内 tail，以前会被静默丢掉。
  - **多 tail 顺序不再错乱**：旧版 `elem.insert(i+1, ...)` 的 `i` 取自插入前快照，每插一个后面下标就错位，实测把 `t2` 插到了 `<bar>` 前面。
  - **`@数字` 转换不再丢上下文**：旧版切段后逐段单独跑 lookbehind 正则，边界判据失效（`@1 和 abc@1` 两个都被转、邮箱 `x@12345.com` 被误转）。现在一次 `finditer` 扫原文，判据都在原文位置做。
  - `text_at_exclude_domains` 配成 `null` 不再抛 `TypeError`。
- **`_fix_at_tags` 死分支清理**：旧版 `elif` 条件与 `if` 完全相同（永不执行），且 `<at user_id="123">456</at>` 会静默丢弃原文本；现在行为明确且有 debug 日志。
- **语音拆分"只有语音时丢弃 @/回复"**：这是既有**刻意取舍**（保证语音消息干净），1.5.0 **不改变行为**，只补 debug 日志让它可观测、可排查。
- **反斜杠转义标签的歧义消解**：`<\/msg>` 有两种可能 —— 模型打错的**真闭合标签**（`好嘞，热搜榜！<\/msg>`）或 bot 正文里**讨论这个 token**（`你说的 <\/msg> 这个写法不对`）。现在 `fix_xml` 会两条路径都跑并择优：若"当作真标签"会弄坏结果、或会把消息切碎成更多条，就按正文处理、保留 token；否则按真标签还原。实测误伤从 4/6 降到 1/6，而"真修复"仍 6/6 未被削弱。
- **提升 `<text>` 内嵌套元素的内容**（新增 `_lift_nested_text_content`）：框架只读 msg 直接子元素的直接文本，所以 `<text>要写成 <msg><text>你好</text></msg> 这样</text>` 里的"你好"和" 这样"用户**完全看不到**（实测旧版只显示"要写成"）。bot 在正文里讲解标签用法时会写出这种嵌套，属于常见场景。现在会把嵌套子元素按文档顺序提为 msg 直接子元素、文字片段重建为 `<text>`；嵌套的 `<msg>` 会"拆壳"摊平（msg 非注册标签，留着会被框架整块跳过）；原 `<text>` 自身的 tail 也接住。只对 `<text>` 生效，`<img>` 等有语义的子元素不动。

### 1.4.0 新增

- **提取 text 内嵌套的 At 标签**（`extract_at_from_text`，默认开）：模型经常把 `<at>` 写进 `<text>` 内部（如 `<text>那这样 <at>123</at> 能收到不</text>`），而框架解析只认 msg 直接子元素的 at，导致真@失效、消息里只剩 @数字 文本。开启后自动把 text 内嵌套的 at 提升为 msg 直接子元素，其余文字按原顺序拆成多个 text 包回原位置，顺序不变；仅处理 text 直接子级的 at，更深层嵌套（如 text > foo > at）不动

### 1.3.0 新增

- **msg 外杂散内容统一处理（对齐框架原生语义）**：框架对 <msg> 之外的内容本来是「已注册标签执行、未注册标签静默跳过、全部原文进记忆」，但插件的切块器会丢弃 msg 之间的散内容、还会把未注册标签里的 <msg> 字样当成真消息边界。现在切块器改为位置感知（不再丢弃任何散段），并按身份统一分流：
  - **杂散文字**（msg 前/之间）：包成 <msg><text> 发出——以前直接丢弃，模型的开场白、过渡句不再神秘消失
  - **忘包 msg 的已注册功能标签**（mimo_tts/record/file/sticker 等）：自动补包 <msg> 生效——以前夹在消息之间的语音/图片会丢，内容零转义（file/record 的 URL 不受影响）
  - **未注册标签**（reasoning/think/foo 等）：内部规范化转义后原位保留在 root 级——用户不可见、原文形态进记忆，伪思考约定不失传，草稿 <msg> 不会误发（覆盖并推广了 1.2.1 的 reasoning 处理）
  - **已注册 root 标签**：原样透传，框架正常执行
  - **未闭合尾巴**：注册标签自动补全闭合（救回没写完的内容），未注册标签剥到末尾
  - **代码围栏整体转义**：围栏 ``` 内的 `<foo>`/`<msg>` 等只是代码文本，以前会被当成标签静默跳过（用户看到的代码缺行）或误导切块器把围栏切开；现在围栏内整体转义、逐字显示，未闭合围栏剩余内容全当代码
  - **健壮性修正**：带属性的自闭合标签（如 `<record url="..."/>`）不再被误判为未闭合而误删/误补闭合；root 级透传块的属性与内容统一过裸字符转义，裸 `&` 不再能炸掉框架解析；注册标签缓存未刷新时以框架内置标签为初始保护名单
- 配置项「剥离内联 reasoning 思考块」更名为「处理 msg 外杂散内容」（键名不变，旧配置无缝迁移）

### 1.2.1 修正

- **内联 reasoning 从「一刀切剥离」改为「隔离-转义-保留」**：1.1.4 的剥离修掉了思考块里 `<msg>` 草稿被当真消息发出的问题，但剥离后思考块不会进记忆——模型在历史里看不到自己用 `<reasoning>` 包规划的范例，容易逐渐忘记这个约定，反而把规划当正文裸发出去。现在闭合的思考块会被隔离出来、内部整体转义（草稿 `<msg>` → `&lt;msg&gt;`，裸特殊字符失效化）后放回输出最前：框架解析时静默跳过（用户不可见）、切块器不会把草稿当边界、记忆完整保留伪思考约定；未闭合尾巴仍剥到末尾。配置项更名为「处理内联 reasoning 思考块」

### 1.2.0 新增

- **text 包裹默认改为黑名单模式（可切换）**：以前的白名单赦免模式会把所有未豁免标签的内容都包进 `<text>`，其他插件的自定义标签（handler 只取直接文本）因此拿到空值、内容静默丢失（原已知 bug #2），用户只能逐个手动豁免。现在默认信任已包裹的内容：只包 msg 下落单的文字和「强制包裹黑名单」内标签的文字，其余标签一律不动；whitelist 可切回旧行为。注意：老用户升级后配置里没有 `wrap_mode` 键，框架会补默认值 blacklist，行为随之切换到新模式
- **新增「强制包裹黑名单」**（`force_wrap_tags`）：仅黑名单模式生效，名单内标签里的文字强制包进 `<text>`；同一标签同时在不包裹名单和黑名单时，不包裹优先（保护已注册自定义标签）

### 1.1.4 修复

- **内联 `<reasoning>` 思考块泄漏**：部分渠道/模型会把思考过程以 `<reasoning>` 标签写进正文（而不是 reasoning_content 字段），其中常含 `<msg>` 草稿、示例消息。旧版切块器会把思考里的 `<msg>` 字样当成真消息边界，导致思考内容被兜底发出、示例消息当真题发送、正式消息重复发送。现在处理前会先剥离内联 reasoning 块（未闭合的剥到末尾，与框架"未知标签跳过"语义对齐），可通过「剥离内联 reasoning 思考块」配置关闭

### 1.1.3 修复

- **空消息 `<msg/>` 不再丢弃**：`<msg/>` 是 AI 合法的「静默」操作，框架会自行优雅处理。旧版丢弃空块会让 `resp.text_response` 变成空字符串，导致：①下游插件按 `<msg/>` 正则检测静默时失效；②记忆里写入的是空字符串而不是 `<msg/>`，AI 无法从历史中区分「说了话」和「选择了闭嘴」，也学不到静默是良性操作。现在原样透传

### 1.1.2 修复

- **[3p] 标记对跨消息不触发**：AI 有时把 `[3p]` 写在一条消息、`[/3p]` 写在另一条，折扇留穗只在单条消息内匹配标记对导致无法触发转发。新增「合并跨消息的 [xxx] 标记对」（默认开）：自动把横跨的纯文本消息合并为一条，让标记对落在同一消息中
- **兜底剥离不吃代码**：「兜底时剥离结构性标签」现在只剥代码围栏 ``` 之外的结构标签，围栏内的代码逐字保留（如代码里的 `<img>`、`<json>` 等与框架同名的标签不会再被吃掉）；围栏未闭合时剩余内容保守地全部当代码保留

### 1.1.1 修复

- **`<msg/>` 自闭合吞消息**：空消息 `<msg/>` 后跟其他消息时，旧切块逻辑会把两条吞成一块导致解析失败、戳一戳等内容被兜底成文字。现在自闭合 msg 独立成块；未正常闭合的 msg 遇到下一个 `<msg` 也会正确截断
- **兜底不再显示一坨 XML**：终极兜底从「整段转义」改为「剥离结构性标签、只留文本」，例如 AI 输出了残缺嵌套的 `<text>` 时，用户看到的是干净文字而不是 `<text>...</text>` 原文（需要逐字保真的场景可在配置中关闭「兜底时剥离结构性标签」）
- **空块识别**：`<msg />`（带空格）现在也会被正确丢弃

### 1.1.0 新增

- **裸特殊字符转义**：AI 输出里带代码、payload、URL 参数（含未转义的 `&`、`<`，如 `<?=`、`&config=`）时，旧版会直接解析失败、消息发不出。现在会先转义再解析，这类内容一次修好，不再走官方"再调一次 LLM 修格式"的慢速兜底
- **终极兜底**：所有修复手段都失败时，整段内容转义为纯文本消息发出，保证消息不丢、进入记忆的永远是良构格式
- **中间步骤旁白也修复**："仅处理最终消息"默认关闭。经核实，工具调用（function calling）是 openai 库处理的结构化字段，与文本完全隔离，修复过程不会干扰工具调用；而中间步骤 AI 说的"话"同样会被发送并写入记忆，不修复会污染记忆
- **自定义不包裹标签名单**（`no_wrap_tags`）：名单内标签的内容不会被包进 `<text>`。内置保护 `mimo_tts`，可自行追加其他插件的标签（填纯标签名即可，如 `mimo_tts`，带不带尖括号都能识别）
- **摊平嵌套**：名单内标签被模型错误嵌套时（如 `<mimo_tts><text>内容</text></mimo_tts>`）自动剥成纯文本，防止内容在解析阶段静默丢失
- **语音消息拆分**：语音（官方 `<record>` 与 `<mimo_tts>` 均生效）自动拆成单条干净消息发送，@/回复迁移到文字消息，避免 QQ 上语音无法正常显示
- **空行分段拆消息**（可选，默认关闭）：单条消息内的空行分段拆成多条发送，模拟真人分段说话；含代码围栏的消息整条不拆

</details>

## 1.安装和使用方法

解压成文件夹放入 `data\plugins\` 即可。首次安装后，推荐重开一次会话，否则可能会不正确生效（例如ai说话中间带空行而不是拆分消息，但你也可以通过开启空行分段配置项来解决）。

## 2.配置项一览

| 配置项 | 默认 | 说明 |
|--------|------|------|
| 启用插件 | 开 | 总开关 |
| 仅处理最终消息 | **关** | 开启后跳过带工具调用的中间步骤。建议保持关闭（中间步骤旁白也会发送和进记忆） |
| 补全缺失的msg标签 | 开 | 没有 `<msg>` 根标签时自动添加 |
| 修复双尖括号 | 开 | `<<msg` → `<msg`；**仅当右边名字确实是标签时**才折叠，不会吃掉 `a<<b`、`1<<2` 这类正文运算符 |
| 修复反斜杠转义的标签 | 开 | `<\\/msg>`、`<\\msg>` → `</msg>`、`<msg>`。模型从 JSON/正则习惯串味时常写出 `<\/msg>`，不开会把 `&lt;\/msg&gt;` 原样发给用户 |
| 转义裸特殊字符 | 开 | 未转义的 `&`、`<` 转为合法 XML，代码/payload 类内容必开 |
| 代码围栏整体转义 | 开 | 围栏 ``` 内整体转义为纯文本，代码逐字显示，不被当成标签跳过或切开围栏 |
| 终极兜底为纯文本 | 开 | 修复全失败时兜底发出，保证不丢消息 |
| 兜底时剥离结构性标签 | 开 | 开：只留干净文本；关：整段转义逐字保真（payload 场景建议关） |
| 修复 At 标签格式 | 开 | `<at user_id="123"/>` → `<at>123</at>` |
| 提取 text 内嵌套的 At 标签 | 开 | 模型常把 at 写进 text 内部（如 `<text>那这样 <at>123</at> 能收到不</text>`），框架只认 msg 直接子元素的 at 导致失效；开启后自动提升为 msg 直接子元素，文字按原顺序拆成多个 text，顺序不变 |
| 不包裹标签名单 | `["mimo_tts"]` | 名单内标签不包 `<text>`，可自行追加 |
| 摊平不包裹标签内的嵌套 | 开 | 剥掉名单内标签被错误嵌套的子标签 |
| 语音消息拆分发送 | 开 | 语音单条发，@/回复归文字消息 |
| 空行分段拆为多条消息 | **关** | 空行分段拆多条发送；含代码围栏或 [xxx] 式标记整条不拆 |
| 合并跨消息的 [xxx] 标记对 | 开 | [xxx] 与 [/xxx] 分散到多条消息时合并为一条，保证折扇留穗等插件识别 |
| 处理 msg 外杂散内容 | **关**（1.5.0 起） | **关**：`<msg>` 外的**裸文本**（模型的规划/旁白/**心声**）不发出去，避免思考过程暴露。其余散段仍按身份分流：**未注册标签块**（`reasoning`/`think`）原样透传（用户不可见、原文进记忆）；**忘带 msg 的功能标签**（语音/图片/@/表情）与含 `[xxx]` 标记的文本**照样补包**。**开**：`<msg>` 外的散文字也包成消息发出（会看到心声，如「让我想想…我该查一下」）。两种状态下「未注册标签结构保护」都无条件执行（1.5.1 起）。
| 未注册标签结构保护 | 内置 | 无需配置：`_handle_unclosed_tail` 与 `_protect_stray_blocks` **不受总开关影响**。前者保证未闭合 `reasoning` 不会吞掉后面的真消息（在下一个 `<msg>` 前补闭合），后者保证思考块内的 `<msg>` 草稿不会被当成真消息发出（内部转义）|
| 文本 @数字 转 at 标签 | 关 | 实验性，AI 经常输出无效 @数字 时再开；边界判据在原文位置判定，不会因切段丢上下文 |
| 提升 text 内嵌套元素 | 内置 | 无需配置：`<text>` 里嵌套的 `<msg>`/`<text>`/`<emoji>` 等会被提为 msg 直接子元素，其文字不再丢失（框架只读直接子元素的直接文本）|

## 3.已知的bug

（1）私聊时，如果启用了输入状态相关插件，当AI主动戳一戳你时，其输入状态显示可能无法停止，需要你再跟ta对话一次（再调用一次llm）来结束。

（2）可能有一些使用场合，一些无需包裹&lt;text>标签的内容也被包裹。1.2.0 起大火可通过使用标签黑名单模式，或白名单的"不包裹标签名单"配置自行豁免对应标签；如仍有没考虑到的情况，欢迎反馈。

（3）**「处理 msg 外杂散内容」1.5.0 起默认关闭** —— 这是**有意的隐私改动**：开启时，模型写在 `<msg>` 外面的**规划/心声**会被当成消息发出去。实测：

| 模型输出 | 关（默认）用户看到 | 开用户看到 |
|---|---|---|
| `让我想想该查一下\n<msg><text>今天晴</text></msg>` | 只有 `今天晴` ✓ | ⚠ 泄漏 `让我想想该查一下` |
| `<msg><text>A</text></msg>等等先确认城市\n<msg><text>B</text></msg>` | 只有 `A` `B` ✓ | ⚠ 泄漏 `等等先确认城市` |
| `我需要先确认意图<msg><text>明白了</text></msg>` | 只有 `明白了` ✓ | ⚠ 泄漏 `我需要先确认意图` |
| `好嘞！<msg><text>我这就去查</text></msg>` | 只有 `我这就去查`（**开场白不发**） | `好嘞！` + `我这就去查` |

**关闭不影响修复能力**：忘包 `<msg>` 的功能标签（语音/图片/@/表情）和含 `[xxx]` 标记的文本**照样补包**（细粒度分流，只挡裸文本）；裸回复补标签、双尖括号、`<\/msg>`、嵌套/畸形修复等其他能力**完全不受影响**。如果你更喜欢让开场白也发出来，把开关打开即可。

**升级时的自动迁移（1.5.1 起为彻底版）**：首次运行做**一次性**配置迁移，并写入标记 `_migrated_strip_reasoning_default`。

判据说明：框架 `_ensure_plugin_config` 只要发现配置缺某个键，就会写入该键的默认值并落盘 —— 所以**跑过 1.4.0 的用户文件里必然已有 `strip_reasoning_block: true`**，无法靠“键是否存在”区分“用户配过”与“框架补的”。因此迁移用**值**判断：

| 升级前文件里的值 | 迁移动作 |
|---|---|
| `true`（= 1.4.0 的默认值，大概率是框架补的） | **改为 `false`** |
| `false`（已关） | 保持 |
| 键不存在 | 设为 `false` |

**只做一次**：迁移后你自己把开关重新打开，之后**重载 / 重启都不会再被改回**（有标记键把关，已用测试锁定该不变量）。

**如果你原本就是主动打开的**：升级后会被关掉一次，请到 WebUI 重新打开 —— 之后就永久保留你的选择。

迁移采用**原子写**（临时文件 + fsync + `os.replace`），只增改一个键 + 一个标记，**任何一步失败都中止、绝不覆盖现有配置**；迁移后当前会话**立即生效**，不用等重载。

（4）「只有语音时丢弃 @/回复」是保证语音消息在 QQ 侧正常显示的刻意取舍，不是 bug；如需保留 @，请在 `_split_voice_chain` 之外处理，或保持该消息同时含文字。

### 与 MiMo TTS 插件的关系

本插件的"摊平嵌套"和"语音拆分"完整覆盖了 [MiMo TTS 插件](https://github.com/znq19/kira-ai-plugin-mimo-tts)的格式修复能力。检测到该插件时会**自动接管**（运行时关闭其 `auto_format_fix`，不修改其配置文件），避免两边重复处理；卸载本插件后 MiMo TTS 的修复功能自动恢复。

### 与其他插件的兼容

- **折扇留穗（3p格式化）**：`[3p]...[/3p]` 是文本标记不是 XML 标签，转义/兜底均不受影响；「空行分段拆消息」遇到 `[xxx]` 式标记会整条不拆，避免标记对被打散导致无法触发转发；标记对被 AI 分散到多条消息时会自动合并为一条
- **pixiv搜图 / DeepWiki**：这两类插件的合并转发是在工具/命令处理器里直接调 `send_forward_msg` 发送的，不经过 LLM 的 XML 文本管线，本插件不会干扰

</details>
